<session title="Devin Codex ACP Connection Failure">
The user was trying to set up **Codex ACP** as a custom agent in Devin Desktop but encountered an error: `"codex-acp" failed to activate: ACP connection closed`.

**Root cause identified:** Devin Desktop's built-in `codex-acp` agent spawns `npx -y @agentclientprotocol/codex-acp@1.6.2`, but the user's npm config had `minimum-release-age=4320` (3 days). Version 1.6.2 was published on 2026-08-20, within the 3-day window, so npm blocked the installation. The process exited with code 1 before the ACP handshake could complete.

**Initial attempted fix:** Added a local registry override at `~/.windsurf/acp/registry.json` pinning to version 1.6.0, but this didn't work because the local registry doesn't override built-in ACP agents in Devin Desktop.

**Final solution:**
1. Remove `minimum-release-age=4320` and `min-release-age=3` lines from `~/.npmrc` using: `sed -i.bak '/^min-release-age=/d; /^minimum-release-age=/d' ~/.npmrc`
2. Install globally: `npm install -g @agentclientprotocol/codex-acp@1.6.2`
3. Set `OPENAI_API_KEY` if Codex CLI isn't already authenticated via browser login
4. Restart Devin Desktop from terminal to inherit Codex CLI auth
5. Enable Codex via: Cmd+Shift+P → Devin User Settings → Agents tab → toggle on Codex
6. Start new conversation and select Codex as the **agent** (bottom-right selector), not just the model

**Additional notes:**
- Devin Desktop uses `~/.windsurf` config directory despite being a different app
- Codex CLI authentication (ChatGPT login) is sufficient; API key is optional if already authenticated
- The agent selector (bottom right) controls which agent runs; the model picker shows models available to that agent
- ACP agents require Pro, Max, or Teams plans and only appear in new conversations
