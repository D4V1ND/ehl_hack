# Running the whole Stockout flow end to end on main


Verified on a clean clone today (Ubuntu 22.04, node 20.18.1, pyenv Python 3.12.8).


1. Setup (once)

run.py needs Python >= 3.11; the system python3 here is 3.10, so point at a 3.11+ interpreter.



bash
git clone https://github.com/D4V1ND/ehl_hack.git && cd ehl_hack
python3.12 run.py setup            # .venv, pip install -e .[dev], ui/ npm install, seeds the SQLite ERP
.venv/bin/pip install -r requirements.txt   # calle-ai; not needed once PR #35 is merged

Without that second line run.py test dies during collection with
ModuleNotFoundError: No module named 'calle' — calle-ai was only in
requirements.txt, which nothing installs. PR #35 moves it into pyproject.toml.

2. Offline check




bash
python3.12 run.py test     # 292 backend tests + UI typecheck, never touches the network

3. Bring the stack up



bash
.venv/bin/python -m uvicorn backend.api.main:app --port 8010
# second terminal
cd ui && NEXT_PUBLIC_DATA_SOURCE=live NEXT_PUBLIC_API_BASE=http://localhost:8010 npm run dev
curl localhost:8010/healthz should read "call_mode":"rehearsal" — that is the
safe default; nothing dials.


4. Walk the case

Either from the cockpit at http://localhost:3000/inventory ("Source this part"),
or straight against the API:




bash
curl -s localhost:8010/inventory | head
curl -s -X POST localhost:8010/cases -H 'content-type: application/json' -d '{"part_id":"PRT-6204"}'
# -> CASE-6204-2RS, stub Devin session (no DEVIN_API_KEY needed)
 
curl -s -X POST "localhost:8010/flow/run?case_id=CASE-6204-2RS&hold_for=SUP-KBY"
curl -s -X POST "localhost:8010/flow/call?case_id=CASE-6204-2RS&supplier_ref=SUP-KBY"
curl -s -X POST "localhost:8010/flow/collect?case_id=CASE-6204-2RS"
curl -s      "localhost:8010/flow/state?case_id=CASE-6204-2RS"
.venv/bin/python -m orchestrator.sourcing publish --case CASE-6204-2RS
What that produced here: 6 suppliers screened, 3 rejected on policy
(blocked origin, missing cert, unaudited), 2 asked, SUP-KBY held back for the
live moment, recommended plan STR-05 (split 4,000 + 6,500, EUR 17,078.27
landed, meets the line stop), and a dry-run PR with 6 procurement artifacts.


Note: POST /flow/publish does not exist — the HTTP route is
POST /tools/publish_pr?case_id=...; the CLI publish is what the README means.

5. Live bits (only when you want them)

Live calling: CALLE_API_KEY, DEMO_CALL_DESTINATION=<your phone, E.164>,
LIVE_CALLS=yes-place-real-calls, FAKE_CALLS=0, then --live.
CALL-E took ~18 min to return a result in rehearsal per the run sheet, so do
not make the re-price the finale.
Real PR on publish: GITHUB_TOKEN + GITHUB_REPO.
Real Devin session on POST /cases: DEVIN_API_KEY, plus PUBLIC_BASE_URL
(the cloudflared URL) so the session can call back.
Bug found and fixed in PR #35

/inventory 500s whenever two requests overlap: SqliteERP shared one
connection across uvicorn's threadpool, so concurrent cursors returned each
other's rows (unit_price came back None). 19 of 20 parallel requests failed;
in the browser it showed as a red "Failed to fetch" banner over the table. Fixed
with one connection per thread + a regression test.
